NoteTree

概要
テキストをツリーで管理できるアプリ

用途
面接のような回答から分岐していく話題の展開をわかりやすくするため

機能
webアプリで
スマホとパソコン対応
undo
redo
空白ドラッグで視点移動
pcではスクロールでズーム調整
スマホでは二つ指でズーム調整
タグ・タイトル・内容はダブルクリックで編集

言語など
ts
サーバーはファイアーベース

仕組み
app {
  DataLayer: Modelを保持する
  CommandManager: Commandを管理するundoやredoもここからCommandに指示を出す
  Renderer: 表示するやつ
}

TagModel {
  id: ModelID,
  name: タグ名,
  color: タグの色,
}

TextModel {
  id: ModelID
  title: タイトル,
  content: 内容,
  tags: TagModelID[], // 1つのテキストに複数のタグを付けられる
  collapsed: boolean, // 内容の折り畳み状態
  position: Vec2,
  size: Vec2,
}

ConnectionModel {
  id: ModelID,
  to: TextModelID,
  from: TextModelID,
}

enum EventID {
  addModel: モデルが追加された,
  removeModel: モデルが削除された,
  updateModel: モデルが更新された,
}

VirtualData {
  編集中の仮データ
}

DataLayer {
  getModelByID(id) // IDからModelを取得

  updateModel(id, VirtualData) // Modelの更新は必ずここから行う

  streamModel(id, callFn: 更新時に呼び出す関数) // RendererでModelの更新を受け取りたい時に使う。callFnは(model: 更新されたモデル) => {}であること

  streamEvent(eventID, callFn) // callFn({ id, event, model, previous })。追加・削除・更新の対象IDを必ず通知する。
  // 追加: model=追加後, previous=null
  // 削除: model=null, previous=削除前（削除済みでもidを通知）
  // 更新: model=更新後, previous=更新前
  // 返り値は購読解除関数。通知のモデルはコピーし、購読者が元データを変更しない。

  removeStreamModel(id, callFn) // 以前つけたStreamを削除する
}

// Modelを更新するためのもの
Command {
  dataLayer: DataLayer // コンストラクターで受け取る
  init() // 編集対象IDや更新用のデータのセット
  execute() // 実行DataLayerを開始更新
  undo() // 実行前の状態に戻す
  redo() // 実行後の状態を再適用
}

CommandManager {
  undoStack: Command[]
  redoStack: Command[]

  execute(command) // コマンドを実行

  redo()

  undo()
}

Renderer_Camera {
  position: Vec2,
  zoom: number,
}

Renderer {
  virtualDataMap: Map<ModelID, VirtualData>

  camera: Renderer_Camera

  init() // 初期化処理CイベントリスナーのセットとかDataLayerにstreamセットとか

  update() // マイフレームAppで呼び出す関数
}

基本的にUIの更新はStreamかCameraの更新時に更新される
UIからCommandを作成CommandManagerを介して実行
編集中はVirtualDataで仮データを表示してCommandで適応後にModelデータの表示に戻す

見た目とそれに関連する機能
画面左に使用できるモデル一覧(TextModel, ConnectionModel)そこからドラッグ&ドロップでTextなどを追加
TextModelはドロップでModelを実際に作成
ConnectionModelはTextModel上にドロップでfromをセットその後from以外のTextModel上をクリックでtoにセットして接続しModelを実際に作成
ドロップするまでやクッリックスまではVirtualDataで少し透明で表示

真ん中はツリー表示用のボード
Textはmacのウィンドウのような見た目で左上の赤黄色緑のボタンはいらない代わりに右上にcontentを畳むための_ボタン
Connectionはfromからtoへの矢印
モデルは複数選択可能
選択物を囲うBBoxを表示
BBoxの右上に削除用xボタン
BBoxをドラッグ&ドロップで一括移動
TextModelは単体でドラッグ&ドロップで移動もできる
TextModelの右下にサイズ変更ハンドルを表示し、ドラッグでsize.x（幅）・size.y（高さ）を変更できる。
・左上の位置は固定し、カメラのズーム倍率を考慮したボード座標でサイズを計算する。
・最小サイズは幅180・高さ80。折り畳み中はハンドルを表示せず、展開時に変更後のサイズを維持する。
・ドラッグ中はVirtualDataと既存DOMの幅・高さだけを更新し、関連する矢印とBBoxも追従する。一時DOMを毎フレーム生成しない。
・ドロップ時に1つのCommandとして確定し、Undo/Redoと保存に対応する。Escまたはpointercancelで取り消す。
・複数選択中でも、サイズ変更はハンドルを操作したカード1枚を対象とする。
TextModelのTagの表示はタイトルの横に少し空間を開けてTag色の丸を横並びで一覧表示
カード上のタグ色をクリックすると、そのカードからタグを外す（タグ自体は削除しない）
カードのタグ一覧の右に仮タグ（灰色の丸）を表示。クリックするとその丸の直下に吹き出しを表示し、未追加のタグを選ぶと即座に追加して閉じる。外側クリック・Escでも閉じる。モーダルや背景の暗転は使わない。
ボードの右の方にに縦のズームバー（カメラのズーム度）ここからズームの変更もできる
ちなみにカメラ移動やズームはCommand操作ではないためundo/redoはできない

画面右にはTag一覧
上部にはTag追加ボタン。クリックすると一覧の末尾に空のタグ名入力欄をその場で表示する。Enterまたは外側クリックで作成、空欄またはEscなら作成しない。タグ名はダブルクリックでその場で編集し、色丸から色を変更する。
Tag名の右のxボタンを押したらTag削除

UIの簡潔さとインライン編集（2026-10-23更新）
・画面の常設文字はNoteTree、テキスト、接続、タグ、保存状態など操作に必要なものだけにする。
・「会話のマップ」「思考の流れを、自由に。」「ボードに追加」、英語の装飾見出し、宣伝文、常時表示の操作説明は置かない。
・ツールの選択中だけ「配置先を選択」「接続元を選択」「接続先を選択」の短い案内を出す。
・タイトルと内容はダブルクリック（スマホはダブルタップ）で元の表示領域を直接入力可能にする。
・編集開始でカードの位置・サイズを変えない。背景暗転、モーダル、保存ボタンは表示せず、入力領域の境界だけ青く強調する。
・入力中はVirtualDataに保持し、カーソル・文字選択・日本語変換が途切れるDOM再作成を避ける。
・外側クリックまたはフォーカスが外れたら確定。タイトルとタグ名はEnterでも確定。
・内容はEnterで改行、Ctrl/⌘+Enterで確定。日本語変換中のEnterは編集確定として扱わない。
・Escは編集開始前に戻す。変更がなければ履歴に追加しない。1回の編集確定を1つのCommandとしてUndo/Redoできる。
・カードへのタグ追加は仮タグの直下の吹き出しだけを表示する。タグ一覧での新規作成とは区別する。

描画更新の分離
・カメラ用の更新フラグとモデル・選択状態用の更新フラグを分離する。
・視点移動・ズームではworldのtransform、背景グリッドの位置・間隔、ズーム表示だけを更新する。モデル取得やDOMツリーの再構築は行わない。
・モデル描画はIDをキーに既存DOMを再利用する。変更のないモデルはHTML解析も省略し、変更があるモデルの属性・テキスト・子要素だけを差分更新する。
・カード、矢印、タグ一覧をフレームごとにinnerHTMLで置き換えない。
・再利用する編集領域の一時イベントリスナーは編集終了時に解除する。
・回帰検証ではMutationObserverでカメラ操作中のDOM追加・削除が0件であることとノードの同一性を確認する。


対象IDを使ったイベント駆動の描画（追記）
・通常のモデル表示更新はDataLayerのstreamEvent通知を起点にする。毎フレーム全モデルのHTMLを生成して比較する方式は使わない。
・RendererのSceneは起動時に一度だけモデルを読み取り、以降は通知されたIDのキャッシュとDOMだけを追加・削除・更新する。
・同一フレーム内の通知はIDのSetに集約し、対象モデルだけを描画する。CommandManagerの通知はUndo/Redoボタン状態の更新に限定する。
・依存関係はインデックスで追跡する。テキストの位置・サイズ・折り畳み変更では接続する矢印だけを更新。タイトル・内容変更で無関係のカードや矢印を更新しない。
・タグの名前・色変更ではタグ一覧の該当行と、そのタグが付いているカードだけを更新。タグ付け変更では対象カードと変更されたタグの使用数だけを更新。
・選択枠・仮データ・接続プレビューはRendererのUI状態として局所更新する。確定済みモデルは必ずCommand→DataLayer→イベント通知を通す。
・カメラ移動・ズームは例外で、transformなど表示座標だけを更新する。
・画面上部に「再描画」ボタンを設ける。全モデルDOMの作り直しは起動時と、このボタンを明示的に押した時に限定する。再描画でモデル、カメラ、Undo/Redo履歴は変えない。
・ヘッダー、サイドバー、ツール、タグ行、カード内側の余白を控えめにし、ボードの作業領域を確保する。

ドラッグ時の一時DOM生成の禁止
・BBoxはRenderer初期化時に1つだけ作成し、選択解除時はhiddenで隠す。再選択、移動、モデル更新、明示的な全体再描画でも同じBBoxを再利用する。
・範囲選択枠と接続プレビューも初期化時に作成し、表示状態・transform・サイズだけ更新する。
・ドラッグ中のカードは既存要素のtransform、矢印は既存SVGパスのd属性を更新する。HTML文字列から差分比較用の一時DOMを毎フレーム作らない。
・ドラッグ中はVirtualDataのみ更新し、ドロップ時にCommandで確定する。
・回帰テストでは接続中DOMの変化だけでなく、HTML解析回数と要素生成回数も測定する。
・画面上部のロゴとNoteTreeタイトルは表示しない。保存状態・再描画・Undo/Redoのみ残す。
・カードヘッダーの高さは40px、左右の余白は9px。本文の余白は上下8px・左右10px、文字は12px・行間1.65・色#4b5563とし、読みやすさを優先する。折り畳み高さと接続線・選択枠の計算もヘッダー高さに合わせる。


アカウントと端末間同期（手動方式）
・Googleアカウントでログインし、PC・スマホは同じUIDのusers/{uid}/boards/defaultを利用する。
・画面上部にログイン／ログアウト、保存、同期を用意する。
・ページ起動／ログイン時にボードを一度だけ読み込む。常時購読・定期通信・自動保存・接続復帰時の自動再送は行わない。
・編集内容は端末内に自動退避する。クラウドへの反映は「保存」または「同期」を押した時だけ。
・保存は変更IDをトランザクションで最新文書へ適用する。同期は保存後に最新文書を一度取得して差分をDataLayerに反映する。変更なしの保存は通信しない。
・新規アカウントにボードがない場合はゲストデータを未保存状態で表示し、明示的な保存時に初めて作成する。
・終了時に未保存ならブラウザの標準確認を要求する。終了時の自動送信はしない。ログアウトも未保存なら確認し、変更はUID別の端末保存に残す。
・同一モデルの同時編集は最後に保存が確定した変更を優先する。手動同期による更新反映・アカウント切り替えでは仮編集と履歴をクリアする。
・起動時のみsessions/last-openを1回読み書きする。異なるセッションが30分以内に開いた記録があれば警告する。現時点の操作中判定ではないことを表示する。
・利用記録は単一の直近記録。定期更新と終了時削除はしないため、閉じた端末の誤検知や長時間開いた端末・複数同時端末の検知漏れがありうる。
・利用警告には通常ボード読込に加えて1読み込み＋1書き込みが必要。厳密な利用状態の常時監視は行わない。
・セッション記録も本人のUIDだけアクセスを許可する。更新したFirestoreルールをデプロイする。

【RendererManager / Board・Note表示 / テーマ】
・App → RendererManager → BoardRenderer / NoteRendererという構成にする。
・RendererManagerは共通ヘッダー（アカウント、保存、同期、Undo/Redo、再描画、テーマ、表示切り替え）と共通ショートカットを管理する。
・各RendererはMain内の自分の領域と操作状態を管理する。右上の一番右にBoard / Noteを置く。
・両Rendererは同一DataLayerとCommandManagerを共有する。切り替えは既存領域の表示/非表示のみで、BoardのDOMとカメラを保持する。非表示Boardの操作は停止する。
・Noteは左にルートからの階層、上にcurrentまでの経路と親リンク、本文にcurrentと直下の子を表示する。親、子、階層のタイトルをクリックするとcurrentを変更する。子孫の本文は一括展開しない。
・接続のfromを親、toを子として扱う。複数の親はすべて親リンクに表示し、経路は最初の親を辿る。循環は既出IDで停止し、ルートのない連結成分も階層に表示する。current削除時は存在するノートへ移る。
・currentのタイトル/本文はダブルクリックで直接編集し青い枠で強調する。blurで確定、タイトルはEnter、本文はCtrl/Cmd+Enterでも確定。Escapeで取消。IME変換中は確定しない。
・NoteもstreamEventのIDとmodelをキャッシュへ反映し、変更のあったDOMだけをパッチする。毎フレームの再生成は行わない。表示状態変更は描画を更新するがModelやUndo履歴は変更しない。
・再描画ボタンは現在のRendererだけを明示的に再描画する。
・テーマボタンはBoard/Note共通のライト/ダークを切り替える。初期値はOS設定に従い、手動選択は端末のlocalStorageに保存する。表示切り替えやテーマ変更でFirebase通信は発生しない。手動保存/同期方針は維持する。

【Note表示の補足】
・Note本文は直上の親（複数ある場合はすべて）、current、直下の子の順で表示する。行番号は表示しない。
・左ツリーは各行に祖先ごとの薄い縦線を置き、各親から続く子孫の範囲と深さを表す。
・各ノートのヘッダーでタグを外すことができ、＋の直下の吹き出しでタグの付け外し、タグ名/色の変更、新規作成ができる。すべてCommand→DataLayer経由で更新しUndoに対応する。新規作成と付与は一つのCommandにまとめる。
・ダークモードは黒に近い背景と薄い境界線を使う。

【検索】
・Cmd+F（Windows等はCtrl+F）でMain右上に検索バーとヒット一覧を表示する。タイトル・本文を部分一致で検索し、大文字小文字/全角半角を正規化、空白区切りの複数語はAND検索する。
・クリック、上下キーとEnterで選択でき、Escapeまたは×で閉じる。選択時も検索UIを閉じる。
・Noteは対象をcurrentにして表示位置へスクロールする。Boardは現在のズームを保って対象を中央に移動し専用の枠でハイライトする。次のpointerdown/wheel/keydownで枠を隠す。
・検索UIはRendererManagerが管理する。ローカルの検索キャッシュはstreamEventで更新し、表示中のヒット一覧も変更へ追従する。アカウント切り替え等では検索状態を消す。検索/移動はModel、Undo履歴、Firebaseを変更しない。
・Boardの検索ハイライトは一度だけ作成し再利用する。カメラ移動はtransform更新のみ。

【2026-10-24 プロジェクト共有・権限・コメント（旧アカウント保存仕様を置き換える）】
1. URLと一覧
   / はGoogleログイン済みユーザーの権限があるプロジェクト一覧。
   /project?id={projectId} は選択プロジェクトのBoard/Note。直リンクも権限チェックする。
   作成者がownerとなる。既存 /users/{uid}/boards/default は名称defaultのプロジェクトへ移行する。旧文書は削除せず、移行中はstate=importing、完了時readyとする。移行は再開可能。
2. データ配置
   /projects/{projectId}: name, roles（正規化Googleメール→owner/editor/viewer）, memberEmails, revision, createdBy, state, updatedAt。
   /projects/{projectId}/models/{modelId}: Text/Tag/Connection/Commentの各Model。
   Model単位に分離し閲覧者のコメントだけをDBルールでも許可する。旧ボードの配列保存は今後使わない。
3. 権限
   owner: 全Model編集＋Googleメールごとのロール変更・アクセス解除。
   editor: 全Model編集（権限管理は不可）。
   viewer: 本文・タグ・接続の参照と自分のコメント追加/編集/削除。
   Google認証・確認済みメールをDBルールで検証。本人のメールを含むmemberEmailsで一覧を検索し、無制限の一覧読み込みは許可しない。
   最後のownerは解除不可。ロール変更は明示的な「権限を保存」で即時反映し、招待メールは送らない。
   CommandManagerにもガードを設け、権限変更後のUndoによる本文編集を防ぐ。
4. コメント
   CommentModel={id,type:'comment',to,title,content,authorUid,authorEmail,authorName,createdAt}。
   タグ・座標・サイズは持たず、toは対象TextModel ID。作者は作成時の認証ユーザー。
   Note: 対象TextModel下に字下げ・薄色で表示、ヘッダーのタグ相当位置に作者。Board: タグ一覧下にコメント一覧。クリックでtoへ視点移動し検索と同じ一時ハイライト。
   対象Text削除時にコメントもCommand内で削除しUndo対応。閲覧者はto/作者を変更できない。
5. 手動保存と競合
   自動同期/自動クラウド保存はしない。初回読込と手動同期時のみモデル取得。
   クライアントの最終読込/保存revisionを保持。保存transaction内で最新revisionと比較。不一致なら書込みを行わず確認モーダル。承認したrevisionと再比較してから変更IDだけを適用する。確認中の追加変更も再確認。
   中止・通信失敗は下書きを保持。全件上書きせず未変更IDは保存しない。同じModelは承認された今回の変更が優先。
   Model変更とrevision更新は原子的に行う。DBルールでもrevision変更を伴わないModel書込みを禁止。
   大量保存はowner/editor350件、viewer10件で分割し各回revisionを確認。失敗時は一部保存済みとなり得るが下書き全体を保持して再試行する。
   旧「30分以内に開いた別端末」の利用記録は廃止し、保存前revisionチェックで実際の変更を検知する。
6. 端末保存と切替
   下書きはUID+projectIdで分離しbaseline revisionを含む。未保存で一覧へ戻る/ログアウト/終了する際は確認する。
   ロール変更で許可されなくなった下書きはrestricted-backupキーに退避し、現在の権限で許可される内容だけ復元する。
   プロジェクト/ユーザー切替時は旧応答を無視し、入力状態・選択・検索・履歴をリセットする。初回読込に失敗した場合は編集を開始しない。
7. デプロイ
   npm run build 後、Hostingとfirestore:rulesを両方デプロイする。Firestore新ルール未適用では共有プロジェクトを読み書きできない。

【Note階層の並び替え】
・TextModelにindex:number（0以上の整数）を追加。新規作成時に順番を設定する。旧データにindexがない場合は0として安定ソートし、並び替え時に対象兄弟のindexを0始まりで振り直す。読み込みだけで全件を書き換えない。
・Noteの左ツリー、ルート一覧、親と子の表示はindex昇順。同値の場合は元の並び順を維持する。indexはTextModel単位のため複数親がある場合も共通の順番を使う。
・左ツリーの行をドラッグし、上端25%で前、下端25%で後、中央50%でその行の最初の子に挿入する。ツリー末尾の余白にドロップするとルート末尾へ移動する。
・ドラッグ中は挿入位置と階層を青い線で表示。線は初期化時に一度作り、座標と表示状態だけ更新する。上下端で自動スクロール。Esc/キャンセル/表示切替で中止する。
・適用時は移動TextModelへの既存の入力Connectionをすべて削除し、新しい親からのConnectionを新IDで作成。ルートへの移動時は作成しない。移動TextModelから子への接続は維持する。複数親は移動先の親1つに統一される。
・index更新とConnectionの削除/追加は1つのCommandにまとめてUndo/Redo可能。確定はDataLayerのイベント経由で両Rendererに反映する。ドラッグ途中はModelやDBを更新しない。
・自身/子孫の下への移動、存在しない移動先、順序が変わらない操作は何も変更しない。閲覧者はドラッグ不可。保存は従来どおり手動で行う。
・Firestoreルールにindexを追加し、旧データのindex欠落も引き続き許可する。Hostingとルールを両方デプロイする。

■ Noteの子ノート追加・接続時の順序
・親/current/子のパネル一覧の直下に「＋」を表示する（オーナー・編集者のみ、currentがある場合）。
・押すとcurrentの子としてTextModelとConnectionModelをまとめて作成する。currentは維持し、子の末尾に表示する。1回のUndoで追加を取り消せる。
・Noteでの追加およびBoardでのコネクション接続時、接続前の親の子TextModel数を接続先TextModelのindexに設定する。
・欠番・重複・旧データのindex欠落がある場合も末尾を保証するため、既存の子を現在の順番のまま0から詰め直す。すでに同じ接続がある場合は何もしない。
・ツリーのドラッグ＆ドロップは指定した挿入位置を優先する。

■ テキストエクスポート
・共通ヘッダーの「エクスポート」で現在のプロジェクト全体をUTF-8（BOM付き）の.txtに保存する。ファイル名はプロジェクト名。
・ルートは「title」「・content」、子は「ー子title」「　・content」。以降は階層ごとに全角空白を1つ増やす。本文の複数行は各行に「・」を付ける。
・親のないTextModelから子をindex順に出力する。タグ・コメントは含めない。
・複数親のノートは各枝に表示し、循環接続はその枝の再訪を止める。ルートのない循環部分も出力する。
・手元の最新データを書き出すだけで、クラウドへの保存・同期は行わない。

■ サイドパネルの伸縮
・Noteのヒエラルキーと本文の境界、Boardのモデル追加一覧／キャンバス／タグ・コメント一覧の境界に細い線を置く。
・境界線をドラッグするとパネルの割合を変更する。見た目は1px、操作領域は9px。操作中・フォーカス時は青で強調。
・狭い画面でBoardが上下配置になる場合は横線を上下にドラッグして高さを変更する。
・割合を端末内に保存し、画面サイズに合わせて調整する。本文・キャンバスの最低領域を確保する。
・伸縮中は既存の境界線とCSSサイズだけを更新し、Modelの更新・カードの作り直し・クラウド保存を発生させない。
・矢印キーでも調整でき、Escまたは操作キャンセルで元の割合に戻る。閲覧者も調整可能。

■ 本文の表・太字表示
・BoardとNoteのTextModel本文は **文字** を太字で表示する。
・「| a | b |」の次の行が「|---|---|」なら最初の行を列名とする表として表示。続く「| 値 | 値 |」形式の各行をレコードとし、形式が途切れたら通常の本文に戻る。
・列数に固定の上限は設けない。空欄は空セル、列不足は空セルで補う。余分なデータ列も空の列名で保持する。セル内の太字も有効。
・ダブルクリック編集時は元の記法を表示し、終了時に表・太字へ戻す。保存・エクスポートは元のテキストを維持する。
・HTML入力は文字として扱い実行しない。表は薄い罫線と見出し背景を持ち、横幅が足りない場合は横スクロールする。
